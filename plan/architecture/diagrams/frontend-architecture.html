Employee360 Frontend Architecture

pnpm monorepo — client apps, shared packages, state-management split & multi-tenant request flow, from plan/architecture/frontend.md

Feature-Driven Structure

  • • Each features/<feature>/ is self-contained: components, pages, queries, schemas, routes.tsx
  • • Admin: auth, users, departments, positions, roles, holidays, categories, audit, dashboard
  • • Employee: auth (passwordless), calendar
  • • Cross-feature UI lives in components/{layout,ui,feedback}/, not inside a feature

State Separation

  • • Server state — TanStack Query only, via @employee360/api-client hooks
  • • Client/UI state — Zustand stores, one authStore + one feature store per app
  • • Forms & validation — React Hook Form + Zod schemas per feature
  • • Zustand strictly holds client-only state: filters, sidebar, active modal, theme

Multi-Tenant API Client

  • • Single Axios instance (client.ts) shared by both apps via packages/api-client
  • • Interceptors attach Authorization Bearer JWT + X-Tenant-ID automatically
  • • Tenant resolved once at login (email domain / token claims), not per-request
  • • generated/ (orval + OpenAPI) keeps client types in sync with the Go backend
