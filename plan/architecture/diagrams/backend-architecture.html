Employee360 Backend Architecture

Clean Architecture (Hexagonal / Ports & Adapters) — layer boundaries, request flow & multi-tenant isolation, from plan/architecture/backend.md

Clean Architecture Layers

  • • Dependencies point strictly inward: Infra → Delivery → Usecase → Domain
  • • Domain has zero dependencies on Gin, GORM, or any driver
  • • Handlers never call GORM or the database directly
  • • Repository interfaces (ports) live in domain, implemented in infrastructure

Multi-Tenancy & Security

  • • Shared DB, shared schema, tenant_id on every table but tenants
  • • tenant.go middleware resolves tenant_id into context.Context
  • • Every repository query/mutation is scoped by ctx tenant_id
  • • JWT (access + refresh) carries tenant_id and role claims

Dev Workflow

  • • make dev / make test — run server and test suite
  • • make migrate / migrate-down — golang-migrate up/down
  • • make bootstrap — seed system tenant, roles, Super Admin
  • • container.go wires every layer from cmd/api/main.go
