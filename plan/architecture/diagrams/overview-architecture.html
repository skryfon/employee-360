Employee360 System Overview

System context and request lifecycle — the detailed companion to the Mermaid diagrams in plan/architecture/overview.md

System Context

  • • Super Admin & Tenant Admin use clients/admin; Employees use clients/employee
  • • Both apps talk to the backend through one shared packages/api-client
  • • A single Go service handles every tenant — isolation is row-level, not per-deployment
  • • See frontend-architecture.html / backend-architecture.html for the internals of each box

Where Tenant Enforcement Happens

  • • Client attaches JWT — never a tenant id — via the api-client interceptor
  • • tenant.go middleware resolves tenant_id from the token into context.Context
  • • Every repository query/mutation is scoped by ctx.tenant_id, not the request body
  • • This is the one chokepoint Invariant 1 depends on — see shared-context.md

Request Lifecycle Ordering

  • • Middleware always runs: request_id → logger → cors → auth → tenant → recovery
  • • Handlers only parse/validate and call a usecase — never touch GORM directly
  • • Usecases coordinate domain + repositories, agnostic of HTTP/JSON
  • • Response returns as a standardized JSON envelope (response/response.go)
